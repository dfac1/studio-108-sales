# Voice Sales Department — план реализации для Studio 108

Дата анализа: 2026-05-04

## 1. Что есть сейчас

В папке уже есть рабочая база знаний для sales-агента:

- `MASTER.md` — единый источник истины: цель, цены, филиалы, правила, ссылки на остальные файлы.
- `lead-workflow.md` — откуда брать лидов и как двигать дату следующего действия в Google Sheets.
- `booking-rules.md` — правила записи, переносов, пропусков и заморозки.
- `offers.md` — цены и исключения.
- `schedule.md` — расписание групповых слотов.
- `teachers.md` — аргументы для продажи через педагогов.
- `faq-objections.md` — готовые ответы на типовые возражения.
- `addresses.md` — адреса, ориентиры и телефоны.
- `pending-conflicts.md` — закрытые конфликты по данным.

Этого достаточно, чтобы собрать первый голосовой MVP, который:

1. звонит или принимает звонок от теплого лида;
2. квалифицирует клиента по возрасту, направлению и филиалу;
3. предлагает 2-3 подходящих групповых слота;
4. отвечает на базовые возражения;
5. фиксирует запись на пробное;
6. обновляет таблицу/CRM;
7. передает сложные случаи человеку.

## 2. Лучший подход для вашего кейса

Для Studio 108 лучший путь — не делать сразу «полностью автономный отдел продаж». На первом этапе нужен узкий голосовой агент только для входящих заявок и записи на пробное занятие.

### Этап 1 — AI voice manager для входящих заявок

Фокус: клиент сам оставил заявку, написал или позвонил. Агент не делает холодный обзвон, а помогает быстро подобрать направление, филиал, время и записать на пробное.

Почему так:

- у вас уже есть лиды в Google Sheets;
- есть понятная цель: запись на пробное и доведение до посещения;
- решение проще юридически и операционно;
- можно быстро измерить эффект по конверсии в запись и посещение.

### Этап 2 — подтверждения и напоминания

После записи агент или автоматизация подтверждает адрес/время и напоминает клиенту о пробном.

Хорошие сценарии:

- «Хочу узнать расписание»;
- «Сколько стоит?»;
- «Подойдет ли ребенку 5 лет?»;
- «Как добраться?»;
- «Можно перенести пробное?».

### Этап 3 — гибридный отдел продаж

AI закрывает рутину, человек берет:

- конфликтные ситуации;
- оплату/возвраты/жалобы;
- нестандартные расписания;
- клиентов с высокой ценностью;
- случаи, где агент не уверен.

## 3. Рекомендуемая архитектура

### Голосовой слой

Так как основной язык — русский, не стоит делать MVP полностью зависимым от одного end-to-end speech-to-speech Realtime-агента. Для русского языка надежнее собрать модульную цепочку:

1. телефония принимает входящий звонок или веб-форма запускает callback;
2. STT распознает русскую речь;
3. LLM принимает решение и вызывает инструменты;
4. TTS озвучивает короткий русский ответ;
5. backend фиксирует запись и отправляет подтверждение.

Почему так лучше для русского:

- можно выбрать лучший отдельный русский STT;
- можно выбрать более естественный русский TTS;
- проще тестировать и заменять слабый компонент;
- проще контролировать ответы;
- проще подключать телефонию и логи.

OpenAI можно использовать как мозг агента, но не обязательно как единственный голосовой контур.

### Рекомендуемая голосовая архитектура для русского

Вариант A — самый практичный для MVP:

- STT: отдельный русский speech-to-text, который хорошо работает с телефонным качеством аудио.
- LLM: OpenAI Responses API или другой сильный LLM для диалоговой логики и tool calling.
- TTS: отдельный русский text-to-speech с естественным женским голосом администратора.
- Телефония: SIP/виртуальная АТС/провайдер с webhooks.

Вариант B — тестовый:

- OpenAI STT + LLM + внешний русский TTS.
- Подойдет, если STT на ваших звонках покажет приемлемое качество.

Вариант C — OpenAI Realtime полностью:

- оставить как экспериментальный трек;
- не брать как основной MVP, пока не пройдены тесты на реальных русских звонках, шуме, перебиваниях, местных названиях и детских направлениях.

### Сервер приложений

Нужен backend, который хранит бизнес-логику и дает агенту инструменты:

- `find_available_slots(age, direction, branch, preferred_time)` — подбор 2-3 слотов;
- `get_price(direction, branch)` — точная цена;
- `create_trial_booking(lead_id, slot_id, name, phone)` — запись на пробное;
- `update_lead_status(lead_id, next_action_date, comment)` — обновление Google Sheets/CRM;
- `send_confirmation(phone, channel, booking)` — подтверждение в SMS/WhatsApp/VK/Telegram;
- `handoff_to_human(reason, summary)` — передача менеджеру;
- `log_call(lead_id, transcript, outcome, recording_url)` — журнал звонка.

Важно: агент не должен сам «придумывать» слоты, цены и правила. Он должен вызывать инструменты и говорить только то, что вернул backend.

### Данные

Markdown-файлы хороши для промпта и обучения команды, но для голосового агента нужно структурировать:

- расписание — в таблицу `slots`;
- цены — в таблицу `pricing_rules`;
- филиалы — в таблицу `branches`;
- педагоги — в таблицу `teachers`;
- возражения — в библиотеку сценариев;
- правила — в системные ограничения и guardrails.

Минимальная структура слота:

- `slot_id`;
- `branch`;
- `weekday`;
- `time`;
- `direction`;
- `level`;
- `age_min`;
- `age_max`;
- `teacher`;
- `is_client_visible`;
- `capacity`;
- `free_places`;
- `price_rule_id`;
- `status`.

## 4. Сценарий разговора

### Обязательный поток

1. Приветствие и контекст:
   - «Здравствуйте, это Studio 108, вы оставляли заявку на пробное занятие по танцам. Удобно минутку?»

2. Квалификация:
   - возраст;
   - направление или цель;
   - удобный район: Развилка, Озеро, Школьная;
   - удобное время: будни/выходные, утро/день/вечер.

3. Подбор:
   - предложить 2-3 групповых варианта;
   - не предлагать «Аренду» и «Индивидуальное занятие»;
   - не предлагать Стрип-пластику на Школьной.

4. Продажа:
   - пробное 300 рублей;
   - Salsa/Bachata — 400 рублей;
   - если клиент спрашивает про абонемент, назвать точную цену по направлению.

5. Закрытие:
   - «Зафиксирую за вами место?»
   - подтвердить день, время, филиал, адрес, педагога.

6. Фиксация:
   - записать в таблицу/CRM;
   - поставить следующую дату действия;
   - отправить подтверждение.

7. Доведение:
   - напоминание за день;
   - напоминание за 2-3 часа;
   - после пробного — follow-up на абонемент.

### Тон агента

Для вашего кейса лучше:

- дружелюбно;
- уверенно;
- короткими фразами;
- без давления;
- с мягким ведением к выбору;
- без длинных объяснений про школу, если клиент не спросил.

Голос должен звучать как администратор студии, а не как робот-продавец.

## 5. Guardrails

Агент обязан:

- говорить только по Studio 108;
- не обещать свободные места без проверки инструмента;
- не менять цену без правила из `offers.md`;
- не предлагать внутренние слоты;
- не спорить с клиентом;
- не делать медицинских/юридических утверждений;
- не принимать финальные решения по спорным возвратам, жалобам и абонементам;
- передавать человеку, если клиент раздражен, просит руководителя, спорит по оплате или просит нестандартное условие.

Фраза при неопределенности:

> «Я уточню у администратора и вернусь с точной информацией, чтобы не сориентировать вас неправильно».

## 6. Что нужно добавить в данные

Сейчас достаточно для MVP, но для стабильной работы не хватает:

1. Свободные места по каждому слоту.
2. Возрастные границы групп.
3. Уровни групп: с нуля / продолжающие / PRO.
4. Правила записи: нужна ли предоплата за пробное, можно ли бронировать без оплаты.
5. Точный канал подтверждения: SMS, WhatsApp, Telegram, VK, Instagram.
6. Кто получает handoff и в каком канале.
7. Рабочие часы, когда AI может звонить.
8. Ограничения по количеству звонков одному клиенту.
9. Формулировка согласия на звонки и запись разговора.
10. Статусы в Google Sheets/CRM и точная схема колонок.
11. Политика хранения записей звонков и транскриптов.
12. Правила post-trial продажи абонемента.
13. Частые вопросы про форму одежды, обувь, длительность занятия, пробное для пары/ребенка, родительское ожидание.

## 7. MVP-функциональность

Для первой версии достаточно:

- входящий звонок или входящая заявка с callback;
- распознавание намерения;
- подбор направления и слота;
- запись на пробное;
- обновление Google Sheets;
- отправка подтверждения;
- handoff человеку;
- журнал звонков;
- транскрипт и outcome;
- dashboard по конверсии.

MVP не должен:

- сам менять расписание;
- сам решать спорные финансовые вопросы;
- звонить холодной базе;
- делать массовый исходящий обзвон;
- работать без логов и прослушки;
- обещать скидки или исключения;
- общаться вне базы знаний.

## 8. Метрики

Отслеживать ежедневно:

- дозвон;
- доля разговоров больше 20 секунд;
- конверсия в запись на пробное;
- конверсия из записи в посещение;
- конверсия из пробного в абонемент;
- причины отказов;
- handoff rate;
- ошибки по расписанию/ценам;
- средняя длительность звонка;
- стоимость записи на пробное;
- стоимость фактического посещения.

Ключевая метрика не «сколько агент поговорил», а сколько людей реально дошло до пробного.

## 9. Юридические и операционные требования

Нужно проверить с юристом, но практический минимум:

- не делать рекламные звонки без предварительного согласия;
- хранить доказательство согласия на коммуникацию;
- предупреждать о записи разговора, если запись ведется;
- иметь политику обработки персональных данных;
- ограничить доступ к записям и транскриптам;
- хранить данные только необходимый срок;
- удалить/обезличить данные по запросу клиента, если применимо.

Пример короткого предупреждения:

> «Разговор может записываться для контроля качества. Продолжим?»

## 10. Рекомендуемый стек

### Быстрый MVP

- Node.js / TypeScript backend.
- OpenAI Responses API / Agents SDK как мозг агента.
- Отдельный русский STT.
- Отдельный русский TTS.
- SIP/виртуальная АТС/телефония через провайдера.
- Google Sheets API.
- PostgreSQL или Supabase для логов, слотов и звонков.
- Небольшая админ-панель для проверки диалогов.

### Почему не только Google Sheets

Google Sheets можно оставить как рабочий интерфейс менеджеров, но realtime-агенту нужен быстрый и надежный слой данных. Лучше синхронизировать таблицу в базу, а не читать markdown/Sheets на каждый ответ в звонке.

## 11. Порядок реализации

### Неделя 1 — подготовка данных

- нормализовать расписание;
- проставить возраст/уровень/вместимость;
- описать статусы лидов;
- описать правила handoff;
- подготовить тестовые сценарии.

### Неделя 2 — голосовой прототип

- собрать модульный русский voice pipeline: телефония → STT → LLM → TTS → телефония;
- подключить инструменты `get_price`, `find_slots`, `create_booking`;
- протестировать 30-50 диалогов вручную;
- настроить транскрипты и логи.

### Неделя 3 — интеграции

- подключить Google Sheets;
- подключить телефонию;
- отправлять подтверждения;
- добавить dashboard результатов.

### Неделя 4 — пилот

- запустить на части теплых лидов;
- слушать записи каждый день;
- доработать промпт и правила;
- сравнить с человеком по конверсии.

## 12. Главный вывод

Ваш кейс хорошо подходит для голосового AI-менеджера, потому что задача узкая, данные уже собраны, оффер простой, а успех легко измерить: запись и посещение пробного занятия.

Но для русского языка лучше делать не монолитный realtime voice-to-voice агент, а модульную систему: сильный русский STT, сильный русский TTS и LLM с инструментами записи. Тогда слабый компонент можно заменить без переделки всей системы.
